# 导航任务操作与逐点执行

## 使用

1. 顶部切到“导航”，点击“新建”，输入名称和类型并创建。先选择“狗当前位置”或“地图打点”，也可稍后通过“添加点”打开取点方式。
2. “狗当前位置”需要有效真实位姿，成功取点后才生成草稿；可修改名称和完整三轴姿态，点击“保存点位”入列。“取消编辑”不覆盖已保存点位。
3. “地图打点”进入连续模式：在空白地图点击或拖动设置方向，松开即新增并自动保存，无需额外保存。选中地图编号只切换当前编辑点，坐标轴仅作用于选中点；拖动坐标轴和修改表单实时保存。点击“完成打点”退出连续模式。
4. 点位行保留定位、编辑、删除三个图标。拖动点位行可调整执行顺序，落点上下边缘显示插入位置；编辑区上下箭头仍可使用。普通编辑需保存；连续地图模式中的编辑实时保存。坐标单位 m，roll/pitch/yaw 使用 XYZ 欧拉角，单位 rad；旧任务缺失的 roll/pitch 自动补零。
5. 任务自动保存在当前浏览器。任务文件箭头随展开方向变化，可导入/导出 JSON。localhost、局域网 IP 和端口分别属于不同存储来源。删除任务通过页面内确认窗确认，取消不删除；面板、弹窗、提示和列表项使用渐隐退出。
6. 在平台设置中连接 ROS，导航状态与定位状态新鲜、定位为 GOOD/USABLE 且导航端空闲时，“开始任务”可用。平台逐点发送目标，仅收到当前编号明确到点后继续下一点；无模拟执行入口。

任务的虚线只表示点位顺序，不是避障规划路线。定位／导航共用三维场景和 ROS 连接，右下角机器人位置信息保持原样。

点击三维任务虚线，在该线段两端点之间立即插入并保存新点，默认朝向由前点→新点、新点→后点的单位切线角平分线计算；折返或重合时保留有效候选朝向。随后显示新点坐标轴供编辑。普通模式下后续位姿修改需保存；连续地图模式下实时保存。点击已有编号或坐标轴优先操作对应点位；按住路线拖动视角不会插点。路线插点与拖动排序均不修改执行中的任务。

编号图标在显示和拾取上优先于坐标轴。坐标轴与编号的世界尺寸随观察距离按平方根增长并封顶，近处控件限制屏幕尺寸，编号屏幕高度不超过 56px。选中场景点位后，任务列表自动平滑滚动到该行居中，首尾行受列表边界限制。

机器人模型、位置信息与“狗当前位置”共用 TF 解析：优先使用配置的机器人坐标系，分别尝试 `/display/tf` 和 `/tf` 的完整变换链。旧默认 `body` 完全没有样本而 `base_link` 可完整解析时，使用 `base_link` 并显示说明；收到 `body` 后恢复优先使用它。自定义坐标系不会自动替换。话题监控有消息并不保证消息包含配置的机器人坐标系。

## 执行规则

- 每次启动复制任务快照，从列表第一个点开始，只下发一个目标。
- 下发成功确认代表目标被接受，不代表已经到达；必须收到当前目标的成功终态反馈才能下发下一点。
- 使用每次运行的 `runId` 和每次下发的 `goalId` 匹配结果。重复结果、旧目标及旧任务结果不推进任务。
- 暂停、继续、取消等待适配器确认。暂停期间收到到达结果只记完成数，继续后再下发下一点。失败和取消不下发后续点位。
- 执行中的任务不可修改、删除或重排点位。执行停止后修改任务会清除旧快照的进度标记。“重新开始”从第一点开始，不是失败点重试。
- 刷新页面保留任务定义，不恢复运行中的调度。真实通信接入时必须另行实现运行恢复和对账；关闭页面不能被当作机器人已经取消。

## 默认 SCAN 导航接入

`useTaskNavigation.ts` 复用平台共享 ROS 连接，注入稳定的 `RosNavigationTransport`；`navigationRunner.ts` 继续负责任务快照和顺序调度。定位/导航切换不重建执行器。

| 话题 | 类型 | 用途 |
| --- | --- | --- |
| `/nav2_goal_request` | `std_msgs/msg/String` | `data` JSON 包含唯一 `request_planid`、`pose.frame_id/x/y/z/yaw` 和任务/运行/点序号上下文 |
| `/nav2_goal_context` | `std_msgs/msg/String` | 匹配当前 request_planid，确认接受、运行阶段与终态 |
| `/nav2_goal_control` | `std_msgs/msg/String` | `data` 为 `{"command":"pause"}`、resume 或 cancel；等反馈确认后更新状态 |
| `/nav_ndt_status` | `std_msgs/msg/UInt8` | 0 无效、1 良好、2 可用、3 异常；不与 /ndt_status 混用 |

- 唯一 goalId 作为 request_planid，每轮运行和每个点重新生成；不自动重试同一请求。
- 成功必须同时满足同编号、`request_completed=true` 与 `last_result="reached"`。planning、path_ready、WAIT_TARGET、goal_active=false 均不表示成功。恢复原因保持当前目标；明确规划失败结束队列。
- 上下文与定位消息接收时效默认 3 秒，目标/控制确认等待 8 秒。时效丢失或发送结果不明时显示状态未知并保留任务锁，不重发、不假定机器人停止；恢复收到当前编号的状态后再对账。定位 0/3 或过期时暂停平台队列推进，不冒充已向底盘发送停止；底盘暂停由导航端负责。
- 人工暂停后可以继续；定位暂停等待导航端恢复。cancel 只在当前连接、新鲜且同编号状态下发出；取消后空编号仅在同一连接周期内等待本次 cancel 确认时接受。断线后空编号不用于推断归属。
- 同浏览器同来源使用控制租约避免多页争用，失去租约禁止发送；租约不是跨设备的服务端互斥。协议不校验控制命令中的 request_planid，现场仍须保证唯一控制源。
- roll/pitch 继续保存在任务文件，但默认 dispatcher 仅消费 yaw，线上的 pose 不发送 roll/pitch。reached 只代表导航端的位置/速度到点条件，不表示最终 yaw 误差达标。
- 不使用 `/nav2_status` 或 `*_internal`，不直接控制 `/cmd_vel`、速度闸门或 `/initial_path`。完整 Nav2 模式需另写协议适配。
- 刷新仅恢复任务定义，不能恢复控制所有权或执行进度；关闭页面不等于取消机器人目标。

`NavigationTransport` 增加可选 `unavailableReason`、`subscribeProgress` 和结果 `uncertain`；隔离测试仍可注入假消息源，但生产无模拟执行模式。

## 验证

在 frontend 目录运行：

```powershell
node tests/navigation-tasks.test.mjs
node tests/navigation-runner.test.mjs
node tests/ros-navigation-transport.test.mjs
npm run typecheck
npm run build
```

编号生成兼容局域网 HTTP 下缺少 `crypto.randomUUID` 的浏览器环境；回归包括该兼容路径、任务文件校验、顺序调度、早到/重复/过期反馈、任务快照、暂停竞态、取消、失败和未接入保护。

组合控件独立回归页面：开发服务器下 `/tests/combined-pose-controls.html`。在有 Playwright 和 Edge 的环境运行 `node tests/combined-pose-controls.test.cjs`，通过实际指针拖动检查平移、三轴旋转、任务三轴旋转、相机锁定和清理。可用 `PLAYWRIGHT_MODULE` 指定 Playwright 模块路径、`NAV_TEST_URL` 指定开发服务器、`BROWSER_CHANNEL` 指定浏览器通道。


导航交互回归：开发服务器运行时执行 `node tests/navigation-workflow.test.cjs`，使用与组合控件测试相同的 PLAYWRIGHT_MODULE、NAV_TEST_URL 和 BROWSER_CHANNEL 环境变量。涵盖连续自动保存、坐标轴拖动不新增、编号选点、渐隐、删除确认及机器狗取点草稿；有效机器人位姿使用浏览器内测试替身，不代表实机联调。

ROS 页面协议测试：`node tests/navigation-ros-workflow.test.cjs` 拦截所有 WebSocket 并覆盖配置请求，验证界面连接、顺序目标、暂停继续、状态断流和空编号取消；不向现场发送目标。真实机器人运动、定位自动恢复和最终朝向效果尚未验证。

暂停/取消未获得确认时，平台仍记住停止后续队列的意图。迟到的到点消息只记录当前点，暂停需用户继续后才发下一点，取消不再发下一点。
