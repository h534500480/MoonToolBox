# 当前平台 Android 适配方案

日期：2026-09-22。当前平台基线：`1b72fa9`；参考安卓分支：`origin/feat/ros_android`，已更新确认其最新提交为 `8b37ac9`。以下保留完整方案；首轮已实现能力分流、确认式悬浮输入、原生键盘遮挡桥接、导航 JSON 系统读写、触屏排序/轻点放置和导航紧凑布局。Android Java 编译与浏览器回归通过，尚未进行 APK 真机验收。大文件性能、计算服务地址配置与全模块触屏操作仍按后续阶段推进。

首轮实现入口：`frontend/src/platform/interaction.ts` 统一容器/触屏/紧凑布局能力；`components/MobileInputOverlay.vue` 管理输入事务；`platform/mobile.css` 仅覆盖触屏布局；`MainActivity.java` 上报 WebView 实际被 IME 覆盖的高度；`RosFilePickerPlugin.java` 提供任务 JSON 系统文档读写。任务状态与 ROS 协议仍共用，不维护两套业务页面。

当前交互差异：桌面可按下拖动设置新点方向；触屏轻点放置，拖动和双指交给相机，放置后用旋转控件调整方向。桌面直接编辑字段，触屏先编辑草稿；键盘收起、取消或关闭目标面板均不提交。Android JSON 导入导出走原生插件，网页走文件输入/下载。不具备计算服务的模块显示说明和返回入口。

## 已确认的问题与可复用实现

- 安卓分支的 `frontend/src/components/RosNavAppPage.vue` 已有悬浮输入草稿、焦点转移、字段名称识别、VisualViewport 监听，以及取消/完成按钮；样式在该分支 `frontend/src/styles.css`。但其悬浮输入框 `@input` 会直接写回原字段，取消只关闭面板，因此不满足“确定后才真的输入”。不能原样迁移。
- 当前 `frontend/android/app/src/main/AndroidManifest.xml` 使用 `sensorLandscape` 和 `adjustNothing`；`MainActivity.java` 将全部窗口 Insets 消费掉。键盘覆盖 WebView 时仅靠网页窗口高度变化不可靠；旧分支按屏高比例估计键盘高度也只能作为兜底。
- 当前任务面板主要依赖宽度断点和固定 top/bottom 数值；横屏手机可能很宽但可用高度很低，左右面板、底部按钮与位姿信息仍同时出现，容易相互遮挡。
- 当前 `nativeFilePicker.ts`、`RosFilePickerPlugin.java` 和 `useNavigationController.ts` 已具备原生文件选择、复制到私有目录、本地 PCD 预览链路；导航任务 JSON 仍走网页 File 输入和 Blob 下载。原生文件选择会临时切到竖屏，需要统一返回时的状态恢复。
- 当前任务排序用 HTML 拖放，场景选点使用鼠标事件；应补充明确的触屏手势支持。PCD、切片、IMU 等部分计算仍依赖 FastAPI/C++，不能把 Android 本机路径直接当成后端机器路径。

## 第一阶段：统一悬浮输入，优先完成

新增全局移动端输入层，例如 `MobileInputOverlay.vue` 与 `useMobileInput.ts`，挂在应用根部，通过 Teleport 显示在普通弹窗之上。保留当前暖灰、浅米色风格，不迁移旧版深色样式。

交互顺序：点击原字段 → 复制字段值到独立草稿 → 焦点进入键盘上方的悬浮输入框 → 点击确定 → 校验成功后一次性写回。取消、系统返回、关闭所属面板均丢弃草稿，保留原值；键盘收起不自动提交。切换编辑字段时也不得隐式提交上一个字段。

- 输入层显示字段名、完整可横向滚动的输入值、必要单位、取消与确定；错误信息留在输入层，不弹新窗口。
- 覆盖任务名称、点位名称、XYZ、roll/pitch/yaw、ROS 地址、话题、数值参数和路径文本。文件、滑块、开关、只读字段不接管。
- 数字先用文本草稿承载，允许输入过程中的负号、小数点和指数，再在确定时进行有限数值、范围与精度检查。不得把空字符串误转为 0。
- 处理中文组合输入，候选字确认阶段的 Enter 不等同于完成。数字键盘缺少负号时提供符号操作；多行字段保留换行。
- 通过显式字段提交回调或公共指令对接 Vue 状态，避免原字段因失焦而提前自动保存。连续打点时也只在用户确定后更新点位。

## 第二阶段：键盘、安全区与面板布局

原生端读取 IME、系统栏和刘海 Insets，转换为 CSS 像素并通知前端；网页环境使用 VisualViewport 作为兼容路径。输入层贴在键盘上沿。系统已缩小视口时不再次扣除完整键盘高度，避免重复抬升。保留三维相机状态，键盘开合不自动复位或重新适配整个地图。

布局依据可用宽度、高度和触摸设备能力共同选择，不能只按宽度判断：

| 场景 | 面板规则 |
| --- | --- |
| 大屏/平板横屏 | 空间足够时保留任务列表和详情并排，限定面板高度并内部滚动 |
| 手机横屏、低高度窗口 | 同时只展开一个主要工具面板；任务列表进入详情后收起，详情提供返回入口 |
| 窄屏/竖屏 | 使用单个工具抽屉或底部面板，保留关闭入口与可见三维区域 |
| 输入期间 | 仅当前输入层占据键盘上方空间；次要设备信息和工具条暂时收起，恢复后回到原位置 |

统一层级：三维场景 → 常驻状态与导航控件 → 工具抽屉 → 确认弹窗 → 输入层。统一管理面板开启状态，避免靠不断增大 z-index 解决遮挡。底部控制和位姿信息占据不同区域，面板留足滚动底边距；执行中的取消任务入口保持可达，键盘返回不触发任务取消。

## 第三阶段：统一文件入口和存储位置

保留原生选择器，以统一服务封装 Android 与浏览器差异：

- 任务 JSON：Android 系统选择器读取文本，复用现有任务格式和 5 MB 限制；导出使用系统保存位置选择或分享，不依赖 Blob 下载。取消选择不作为错误弹窗。
- PCD/YAML/PGM：复用已存在的本地预览插件；显示原文件名、体积、解析进度与关联文件缺失原因。大文件分块/流式处理，避免整份 Base64 往返；统一缓存管理和失败清理。
- PCD 转换、切片、IMU、后续录包处理：明确区分“手机文件”与“计算服务文件”。需要服务端计算时先上传，再使用服务端返回的路径；配置独立后端地址，不假设 APK 内的 `/api` 就是电脑后端。
- 选择器返回、权限拒绝、进程恢复、同名文件、中文文件名、横竖屏切换都保留当前任务与编辑上下文。临时强制竖屏是否保留，以系统选择器实机表现决定。

## 第四阶段：触屏操作与性能

- 任务列表使用明确拖动手柄及 Pointer Events，区分列表滚动和排序；保留上下移动按钮。实际点击区扩大，图标外观仍保持精细。
- 场景单指选点、拖动坐标轴和移动视角统一仲裁；双指操作相机，第二根手指加入时取消待插点手势。路线插点加入触摸容差，滑动不插点。
- 点云预览预算和像素比根据设备配置限制；后台暂停非必要绘制，回前台检查 WebGL 和 ROS 连接，不自动恢复导航下发。

## 文件职责和实施顺序

1. 输入和键盘基础：应用根组件、新移动输入组件/组合函数、Android MainActivity 与专用 Insets 桥接；先接任务名称与位姿字段，验证后覆盖其他输入。
2. 页面布局：NavigationWorkspace、NavigationTasks、GlassDrawer、MappingWorkspace 及公共样式；沿用业务状态和同一个三维场景。
3. 文件能力：nativeFilePicker、RosFilePickerPlugin、任务 JSON 导入导出和 API 地址配置；保持 Android 本地预览与后端计算边界清楚。
4. 手势与打包：Nav3DViewer、CombinedPoseControls、任务拖放；使用当前前端构建后执行 Capacitor sync，再构建 APK，不沿用旧的已复制网页资源。

不整分支合并旧安卓页面，以免覆盖当前导航执行协议、建图骨架与视觉风格。

## 验收要求

### 已实现的分辨率预设（2026-09-22）

平台设置顶部新增“分辨率 / 布局预设”，支持自动适配、3200 × 1440 横屏、常规手机与桌面布局，选择即时生效并存到本机。设置显示实际 CSS 可用宽高和像素比：物理 3200×1440 可能对应 800×360 或 1280×576 的 WebView 可用区域，因此预设始终按实际区域限制面板高度，而非把物理像素直接作为 CSS 尺寸。自动模式依据触屏能力、屏幕像素估计和横屏比例选择；手动选择可覆盖自动结果。

定位监控、导航侧栏/详情及建图输入/产物共用顶部与底部留白，长内容内部滚动。常规手机建图用“地图产物 / 建图配置”切换面板；窄屏定位打开话题抽屉时暂时隐藏监控面板，关闭后恢复。布局变化不重建三维场景，不改变通信与任务数据。修改后须重新运行 build:android 并构建、安装 APK，旧安装包不会自动更新。

已通过多像素比浏览器布局回归，真实设备显示缩放、系统栏及软键盘组合尚未验证。

- 横屏手机、平板及窄窗口；至少两种 Android 输入法，包含中文输入、负数、小数、长路径。
- 所有输入时可见字段名和当前草稿；取消不改值，确定只提交一次，中文候选确认不误提交；键盘收起/旋转/返回后无残留遮挡。
- 工具面板和底部操作互不重叠；任何抽屉均可关闭，长列表与确认按钮可滚动到达。
- 文件导入成功、取消、拒绝权限、异常格式、大文件与导出保存可用；明确文件属于手机还是后端。
- 点位选择、排序、插点与双指缩放不互相误触；多客户端 ROS 和逐点导航既有回归保持通过。
- 浏览器测试覆盖输入草稿状态、布局尺寸和业务逻辑；键盘 Insets、系统文件选择器、返回键及后台恢复必须用实机验收。目前仅完成首轮浏览器回归和 Android Java 编译，尚未完成这些真机验收。
